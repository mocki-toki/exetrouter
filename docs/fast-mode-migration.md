# Fast-mode policy: schema 14 to 15

Schema 15 adds nullable `access_tokens.fast_mode` (0, 1 or NULL) and `disabled` (0 or 1, default 0). NULL inherits the operator-wide `fast_mode` configuration, which defaults to false. Existing tokens and credentials are preserved with NULL and enabled. Rotation copies both settings. No usage or conversation payloads are added. Update all binaries using the same state together; the operator should take and verify a private snapshot before upgrading. Restart the service after changing the global config; token changes apply on the next generation.

Rollback to a schema-14 binary requires an operator-reviewed migration, not a routine image downgrade: stop writers, retain a private schema-15 snapshot with both keys, rebuild `access_tokens` from the schema-14 definition while preserving every original column, row, index, foreign key and trigger but omitting `fast_mode` and `disabled`; verify `PRAGMA foreign_key_check` and `PRAGMA integrity_check`, then set `user_version=14`. Record and explicitly decide how to handle any non-NULL token overrides or disabled tokens first: the old binary has no Fast policy and would reauthorize disabled tokens and forward the client Fast choice. Restoring an earlier snapshot instead may discard newer accounting or refreshed OAuth credentials. Do not run two copies of the OAuth pool concurrently.
